# IR-0001 全网多平台爆款对标分析与脚本生成系统（条款级规格）

## INV 不变量

- INV-1: 统一数据模型是三平台唯一汇合点——抖音、小红书、视频号的一切采集与多模态提取产物必须先落为统一 JSON（task_id/platform/content_type/author/content_meta/raw_text/timeline_data），核心分析引擎必须只消费该结构且不得包含任何平台特判分支。
- INV-2: ASR 产物必须携带秒级或毫秒级时间戳——无时间戳的转写结果必须被处理层拒绝进入融合阶段，不得以全文拼接形态降级放行。
- INV-3: 采集合规边界不得突破——仅采集公开可浏览数据与已授权自有账号数据，频控或代理 IP 池机制必须默认启用，禁止存在无频控的直连采集路径与账号密码代登录路径。
- INV-4: 任务执行必须全异步化——单条内容的失败必须记录状态并跳过，同批次其他内容的处理不得因此阻塞或中止。
- INV-5: 大模型调用必须经统一 LLM 网关路由——业务代码不得直连任何具体供应商 SDK，供应商热切换不得要求改动业务代码。
- INV-6: 意图标签集（intent）与 Prompt 模板必须以版本化配置资产存在于仓库内，禁止散落于不可追溯的自由文本。

## BEH 行为

- BEH-1: 当用户录入任一平台的账号链接或 ID 时，系统必须自动判定所属平台、校验账号有效性并拉取账号名称与粉丝数等基础信息。
- BEH-2: 当用户创建对标组并设置筛选条件时，系统必须将账号编入 5-20 规模的组并支持垂类关键词、点赞数、转发数、近期爆款频次四维筛选。
- BEH-3: 当用户在后台手动点击开始分析时，系统必须将该账号加入异步处理队列并返回可查询的任务标识，且不得创建定时全量巡检。
- BEH-4: 当采集通道对指定账号执行采集时，系统必须回溯其近 6 个月发布的全部内容并按平台抓取素材——抖音取视频流、点赞转发元数据与 Top 热门评论，小红书取短视频流、图文图片集、封面图、内页图与文末 Hashtag，视频号取视频流与社交元数据。
- BEH-5: 当同一内容再次进入采集范围时，系统必须经去重机制识别并跳过重复处理。
- BEH-6: 当一条视频完成音轨分离时，系统必须调用 ASR 引擎产出带秒级或毫秒级时间戳的分段转写文本。
- BEH-7: 当视频关键帧或小红书图片进入处理队列时，系统必须执行 OCR 并提取画面花字、字幕与图片内嵌文案三类文本。
- BEH-8: 当同一条内容的标题描述、ASR 与 OCR 文本全部产出时，系统必须按时间轴或图片顺序融合为统一数据模型的完整原始文案 JSON。
- BEH-9: 当大模型拆解引擎接收统一数据模型 JSON 时，系统必须输出含 time_range、script_text、intent 三字段的秒级或段级结构化拆解结果。
- BEH-10: 当拆解目标平台为抖音、小红书或视频号时，系统必须分别执行节奏与 BGM卡点与黄金3秒留存、封面吸引力与种草转化路径与图文排版、社交货币与情绪共鸣的平台差异化分析。
- BEH-11: 当单账号多条视频拆解完成时，系统必须产出显式包含叙事风格、高频词汇、固定结构套路三类要素的自然语言总结。
- BEH-12: 当对标组分析收口时，系统必须产出单账号深度报告与多账号聚合对比报告两类产物，聚合报告必须含量化的跨账号共性特征表述。
- BEH-13: 当分析结论定稿时，系统必须将爆款逻辑抽象为含必含元素清单、时长限制、分镜要求的拍摄 SOP 文档。
- BEH-14: 当用户选择对标账号并输入新视频主题时，系统必须调取该账号爆款逻辑特征并生成含场景描述、口播台词、运镜与画面建议三段结构的脚本草稿。
- BEH-15: 当用户请求导出报告时，系统必须提供 PDF 或 Word 格式导出且导出内容与在线版本一致。
- BEH-16: 当采集请求速率达到频控阈值时，系统必须经代理 IP 池轮换或降频机制继续采集且全程仅触碰公开可浏览数据与已授权自有账号数据。
- BEH-17: 当批次内任一条内容的 ASR、OCR 或 LLM 处理失败时，系统必须记录失败状态、跳过该条并继续同批次其他内容，单条重试次数不得超过 BUDGET-2。
- BEH-18: 当 LLM 供应商配置切换时，系统必须经统一 LLM 网关将调用路由至新供应商且业务代码零改动。

## IFACE 契约

- IFACE-1: 统一数据模型 JSON 的 schema 必须以版本化文件落盘于仓库内，timeline_data 条目必须含 time_start、time_end、source_type、raw_text 四字段且 source_type 取值必须限于 ASR、OCR、Title 三值。
- IFACE-2: 秒级拆解输出必须是机器可解析的结构化 JSON（time_range/script_text/intent），intent 意图标签集（黄金3秒开头、痛点引入、情绪反转、干货输出、引导转化）必须以可枚举配置资产存在。
- IFACE-3: LLM 网关必须暴露统一调用接口并支持本地模型与第三方 API 的配置化热切换，秒级拆解的 Prompt 模板必须版本化于仓库内。
- IFACE-4: 平台差异化分析的三平台分析面（抖音节奏/BGM卡点/黄金3秒留存、小红书封面/种草路径/图文排版、视频号社交货币/情绪共鸣）必须作为独立配置或代码模块存在且互不可替换。

## BUDGET 预算

- BUDGET-1: 本 spec 派生的实现卡按一个 PR 一件事且 diff 低于 400 行的纪律逐卡拆分落地。
- BUDGET-2: 单条内容的 ASR、OCR 或 LLM 处理失败重试次数上限为 2 次，超限即标记失败并跳过。

## DECISION 决策

- DECISION-1: 开源复用选型按 ADR-0091 登记——ASR 采用 faster-whisper（MIT，segment 级时间戳原生输出）、OCR 采用 RapidOCR（Apache-2.0，模型版权面在首个依赖引入 PR 复核）、LLM 网关采用 LiteLLM（MIT）、媒体下载内核参考 yt-dlp（Unlicense）；采集层的 MediaCrawler 与 wx_channel 采取「参考不依赖」裁决——不 vendored、不分发、不直接依赖其代码，本仓以适配器模式自研三平台采集通道。
- DECISION-2: 红队执行采用 CI-Workflows adversary judge-deep 审计（ADR-0082/0067 语义）叠加本地沙盒攻击轮，判定只认 GitHub 侧可回查的运行时证据——沙箱自报数字不采信。
- DECISION-3: 本 spec 由 PM 自著（ADR-0085 决策 5 等价路径）——跨平台多模态数据管线属高决策密度面，不派低决策密度执行者。
- DECISION-4: 平台接入顺序按 IR 质量-速度旋钮收缩——抖音先行、小红书次之、视频号殿后；Top 热门评论情感分析、Word 导出可后置落地；ASR 时间戳、OCR 花字提取、秒级 intent 拆解、三平台统一数据模型四项为不收缩核心。
- DECISION-5: 本仓语言规范按 ADR-0091 豁免为 Python（多模态推理链生态复用），治理基线（gate/org-gate/adversary 双轨 required check、hygiene、REPOS.yaml 申报、依赖审批）不豁免。

## ASSUMPTION 假设

- ASSUMPTION-1: 三平台公开页面的数据接口在实现窗口内可经频控访问，平台反爬升级导致的适配器失效属运维事件，不构成 spec 违约。
- ASSUMPTION-2: faster-whisper 与 RapidOCR 在中文口播与中文花字上的识别准确率满足拆解需要，残余识别错误由 LLM 拆解阶段的语义容错吸收。
- ASSUMPTION-3: 报告与脚本草稿的生成质量以人工评审抽检为准，本 spec 只约束产物结构完备性与证据可回查性。
